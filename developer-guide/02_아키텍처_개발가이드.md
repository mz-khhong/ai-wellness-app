## 1. Hexagonal Architecture 구조

### 1.1. 구조 개요

Hexagonal Architecture는 다음 3개의 주요 계층으로 구성됩니다:

```
┌─────────────────────────────────────┐
│   Infrastructure (Infrastructure)   │  ← 외부 세계와의 연결
│   - Adapter (어댑터)                  │
│     - Web (REST API)                 │
│     - Persistence (데이터베이스)        │
│     - Infrastructure (외부 시스템)     │
└─────────────────────────────────────┘
              ↓ 호출
┌─────────────────────────────────────┐
│   Application (애플리케이션)            │  ← 비즈니스 유스케이스
│   - Service (서비스)                  │
└─────────────────────────────────────┘
              ↓ 사용
┌─────────────────────────────────────┐
│   Domain (도메인)                     │  ← 핵심 비즈니스 로직
│   - Model (엔티티)                    │
│   - Port (포트 인터페이스)              │
└─────────────────────────────────────┘
```

### 1.2. 의존성 방향

**규칙**: Infrastructure → Application → Domain

- **Infrastructure 계층**: Application 계층에 의존
- **Application 계층**: Domain 계층에 의존
- **Domain 계층**: 의존성 없음 (순수 Java 객체)

### 1.3. 계층별 역할

#### Domain 계층
- **역할**: 핵심 비즈니스 로직
- **구성**: `domain/model/`, `domain/port/`
- **특징**: 순수 Java 객체, Infrastructure 의존성 없음

#### Application 계층
- **역할**: 비즈니스 유스케이스 구현
- **구성**: `application/service/`
- **특징**: Domain Port를 통해 데이터 접근

#### Infrastructure 계층
- **역할**: 외부 세계와의 연결
- **구성**: `adapter/web/`, `adapter/persistence/`, `adapter/infrastructure/`
- **특징**: Domain Port 구현, Application Service 호출
  - **Web Adapter**: REST API 엔드포인트 제공
  - **Persistence Adapter**: 데이터베이스 접근 (MyBatis)
  - **Infrastructure Adapter**: 외부 시스템 연동 (Kafka, 외부 API 등)

## 3. 도메인 모델 작성 규칙

### 3.1. 기본 원칙

1. **순수 Java 객체**
   - Lombok 어노테이션만 사용 (`@Getter`, `@Setter`, `@Builder` 등)

2. **패키지 구조**
   ```
   {server}-server/
   └── domain/
       └── model/
           ├── {domain}/          # 도메인별 폴더
           │   └── {Domain}.java  # 도메인 모델
           └── enums/             # Enum 클래스들
   ```

3. **명명 규칙**
   - 클래스명: PascalCase (예: `Admin`, `Manager`, `Customer`)
   - 필드명: camelCase (예: `facilityGroupId`, `createdAt`)
   - Enum: PascalCase (예: `AdminStatus`, `AdminRole`)

### 3.2. 필수 어노테이션

```java
@Getter
@Setter
@Builder
@NoArgsConstructor
@AllArgsConstructor
@Schema(description = "도메인 설명 (테이블: {table_name})")
public class Domain {
    // 필드들
}
```

### 3.3. 필수 필드

모든 도메인 모델은 다음 필드를 포함해야 합니다:

```java
private Long id;                    // Primary Key
private LocalDateTime createdAt;   // 생성 일시
private LocalDateTime updatedAt;    // 수정 일시
```

### 3.4. @Schema 어노테이션 사용

#### 클래스 레벨
```java
@Schema(
    description = "관리자 도메인 모델 (테이블: admins)",
)
public class Admin {
    // ...
}
```

#### 필드 레벨
```java
@Schema(
    description = "관리자 ID (Primary Key, 컬럼: id)",
    example = "1"
)
private Long id;

@Schema(
    description = "이메일 주소 (컬럼: email, UNIQUE)",
    example = "admin@example.com"
)
private String email;
```

### 3.5. MyBatis 매핑 규칙

- 도메인 모델은 데이터베이스 테이블과 **1:1 매핑** 관계
- 필드명은 `snake_case` 컬럼명과 `camelCase` 필드명 자동 매핑 (MyBatis 설정)
- Enum은 `EnumTypeHandler`를 사용하여 매핑

#### 3단계: Adapter 구현
```java
package com.aiwellness.{server}.adapter.persistence.{domain};

import com.aiwellness.{server}.domain.model.{domain}.Domain;
import com.aiwellness.{server}.domain.port.{domain}.DomainRepositoryPort;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Repository;

import java.time.LocalDateTime;

@Repository
@RequiredArgsConstructor
public class DomainAdapter implements DomainRepositoryPort {
    private final DomainMapper domainMapper;
    
    @Override
    public Domain save(Domain domain) {
        LocalDateTime now = LocalDateTime.now();
        if (domain.getId() == null) {
            domain.setCreatedAt(now);
            domain.setUpdatedAt(now);
            domainMapper.insert(domain);
        } else {
            domain.setUpdatedAt(now);
            domainMapper.update(domain);
        }
        return domain;
    }
    
    // ... 나머지 메서드 구현
}
```

#### 4단계: Service 구현
```java
package com.aiwellness.{server}.application.service.{domain};

import com.aiwellness.{server}.adapter.web.{domain}.dto.DomainResponse;
import com.aiwellness.{server}.domain.model.{domain}.Domain;
import com.aiwellness.{server}.domain.port.{domain}.DomainRepositoryPort;
import com.aiwellness.{server}.exception.{domain}.DomainBusinessException;
import com.aiwellness.{server}.exception.{domain}.DomainErrorCode;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Isolation;
import org.springframework.transaction.annotation.Transactional;

@Slf4j
@Service
@RequiredArgsConstructor
@Transactional(isolation = Isolation.READ_COMMITTED)
public class DomainService {
    private final DomainRepositoryPort domainRepositoryPort;
    
    @Transactional(readOnly = true)
    public DomainResponse getDomain(Long id) {
        Domain domain = domainRepositoryPort.findById(id)
                .orElseThrow(() -> new DomainBusinessException(DomainErrorCode.DOMAIN_NOT_FOUND));
        return DomainResponse.from(domain);
    }
    
    // ... 나머지 메서드 구현
}
```

### 4.3. Controller/Service 구조

**규칙**: Controller는 Request/Response DTO만 사용하고, Domain Model 변환은 Service에서 처리

```java
// Controller
@PostMapping
public ApiResponseWellness<DomainResponse> createDomain(@Valid @RequestBody DomainCreateRequest request) {
    return ApiResponseGenerator.success(domainService.createDomain(request));
}

// Service
public DomainResponse createDomain(DomainCreateRequest request) {
    // DTO → Domain 변환
    Domain domain = Domain.builder()
            .email(request.getEmail())
            .name(request.getName())
            // ...
            .build();
    
    // 비즈니스 로직 처리
    Domain saved = domainRepositoryPort.save(domain);
    
    // Domain → DTO 변환
    return DomainResponse.from(saved);
}
```

## 5. Kafka 메시지 발행 (아웃바운드 포트)

### 5.1. 구조 개요

이 프로젝트는 **메시지 발행(Producer)만** 수행하며, 메시지 소비(Consumer)는 `ai-wellness-message-app`에서 처리합니다.

```
┌─────────────────────────────────────┐
│   Infrastructure (Web Adapter)      │
│   - MessageEventController          │  ← 인바운드: HTTP API
└─────────────────────────────────────┘
              ↓ 호출
┌─────────────────────────────────────┐
│   Application (Service)             │
│   - 비즈니스 로직 처리 후 메시지 발행    │
└─────────────────────────────────────┘
              ↓ 사용
┌─────────────────────────────────────┐
│   Domain (Port)                     │
│   - MessageEventPort                │  ← 아웃바운드 포트
└─────────────────────────────────────┘
              ↓ 구현
┌─────────────────────────────────────┐
│   Infrastructure (Message Adapter) │
│   - MessageEventAdapter             │  ← 아웃바운드 어댑터
│   - KafkaTemplate 사용              │
└─────────────────────────────────────┘
              ↓ 발행
┌─────────────────────────────────────┐
│   Kafka Topic                       │
│   - wellness-message-event          │
└─────────────────────────────────────┘
              ↓ 전달
┌─────────────────────────────────────┐
│   ai-wellness-message-app           │
│   - Consumer가 메시지 소비           │
└─────────────────────────────────────┘
```

### 5.2. Common 모듈 구조

메시지 발행 기능은 `common` 모듈에 구현되어 있으며, 모든 서버에서 공통으로 사용할 수 있습니다:

```
common/src/main/java/com/aiwellness/common/
├── domain/
│   └── port/
│       └── message/
│           └── MessageEventPort.java          # 아웃바운드 포트 인터페이스
│
├── adapter/
│   └── infrastructure/
│       └── message/
│           └── MessageEventAdapter.java       # Kafka Producer 어댑터
│
├── controller/
│   └── message/
│       ├── MessageEventController.java         # 테스트용 API (인증 없음)
│       └── dto/
│           ├── request/
│           │   └── MessagePublishRequest.java
│           └── response/
│               └── MessagePublishResponse.java
│
└── config/
    └── KafkaConfig.java                        # Kafka Producer 설정
```

### 5.3. 메시지 발행 사용 방법

#### 1단계: MessageEventPort 주입

```java
package com.aiwellness.{server}.application.service.{domain};

import com.aiwellness.common.domain.port.message.MessageEventPort;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class DomainService {
    private final MessageEventPort messageEventPort;
    
    public void createDomain(DomainCreateRequest request) {
        // 비즈니스 로직 처리
        Domain domain = domainRepositoryPort.save(domain);
        
        // 메시지 발행
        Map<String, Object> event = Map.of(
            "eventType", "DOMAIN_CREATED",
            "domainId", domain.getId(),
            "email", domain.getEmail(),
            "occurredAt", LocalDateTime.now()
        );
        
        messageEventPort.publish("wellness-message-event", domain.getId().toString(), event);
    }
}
```

#### 2단계: 메시지 키 사용 (파티셔닝)

메시지 키를 지정하면 동일한 키를 가진 메시지는 같은 파티션에 배치됩니다:

```java
// 사용자 ID를 키로 사용하여 같은 사용자의 메시지는 같은 파티션에 배치
messageEventPort.publish("wellness-message-event", userId.toString(), event);

// 키 없이 발행 (라운드로빈 방식으로 파티션 할당)
messageEventPort.publish("wellness-message-event", event);
```

#### 3단계: 테스트용 API 사용 (인증 없음)

개발 및 테스트 편의를 위해 인증 없는 API가 제공됩니다:

```bash
POST /api/v1/messages/publish
Content-Type: application/json

{
  "topic": "wellness-message-event",
```

#### Security 설정

메시지 발행 테스트 API는 인증 없이 접근 가능합니다:

```yaml
security:
  public-paths:
    - /api/v1/messages/**  # 메시지 이벤트 발행 API (테스트용, 인증 없음)
```

### 5.5. 주의사항

1. **메시지 발행만 수행**: 이 프로젝트는 Consumer를 구현하지 않습니다.
2. **비동기 처리**: 메시지 발행은 비동기로 처리되며, 실패 시 예외가 발생합니다.
3. **메시지 키 활용**: 파티셔닝을 위해 메시지 키를 적절히 사용하세요.
4. **에러 처리**: 메시지 발행 실패 시 적절한 에러 처리를 구현하세요.

## 6. API 응답 및 다국어 처리

### 5.1. API 응답 구조

#### ApiResponseGenerator 사용
```java
// 성공 응답 (200 OK)
return ApiResponseGenerator.success(data);

// 성공 응답 (201 CREATED)
return ApiResponseGenerator.success(message, data, HttpStatus.CREATED);

// 실패 응답
return ApiResponseGenerator.fail(ApiResponseWellnessCode.DATA_PROCESSING_FAILURE, HttpStatus.BAD_REQUEST);
```

- Swagger UI에서 `Accept-Language` 헤더를 설정하여 언어 선택
- 기본값: `ko` (한국어)
- 지원 언어: `ko`, `en`

#### 메시지 키 사용

```java
// ErrorCode에 messageKey 정의
```

## 7. 체크리스트

새로운 도메인을 추가할 때 다음을 확인하세요:

- [ ] `domain/model/{domain}/` 구조 사용
- [ ] `domain/port/{domain}/` 구조 사용
- [ ] `adapter/persistence/{domain}/` 구조 사용
- [ ] `adapter/web/{domain}/` 구조 사용
- [ ] `application/service/{domain}/` 구조 사용
- [ ] 도메인 모델에 `@Schema` 어노테이션 추가
- [ ] 테이블명과 컬럼명 명시
- [ ] Request/Response DTO 작성
- [ ] Controller는 DTO만 사용, Domain 변환은 Service에서 처리
- [ ] 예외 처리 (`exception/{domain}/` 구조)
